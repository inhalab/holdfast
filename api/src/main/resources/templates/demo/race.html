현재 전략 none

손으로 두 창을 클릭하는 것으로는 동시성을 보여줄 수 없다. 홀드 트랜잭션이 밀리초라 손으로 누른 두 요청은 겹치지 않고, 순차 요청은 none에서도 깨지지 않는다. 이 버튼은 브라우저가 Promise.all로 요청을 한 번에 발사한다.
시드 — 회차·좌석·사용자를 처음부터 만든다 DB가 비어 있어도 이 한 번으로 화면이 돈다. 측정은 계속 seed.sh를 쓴다.

무엇을 보아야 하나. none이면 좌석 하나에 활성 홀드가 여러 건으로 남는다 — 같은 좌석을 여러 사람이 동시에 잡은 것이고, 그것이 초과 홀드(V-2)다. 전략을 걸면 좌석마다 1건이고 나머지는 409로 거절된다.

좌석 수를 늘리면. 요청이 좌석에 돌아가며 흩어진다(1번 요청→1번 좌석, 2번 요청→2번 좌석…). 요청 20개에 좌석 3개면 좌석당 6~7개가 몰리므로, none은 좌석마다 초과 홀드가 생겨 총 홀드가 요청 수에 가까워지고, 전략을 걸면 총 홀드가 정확히 좌석 수가 된다.

요청 수를 20으로 줘도 성공이 6쯤에서 멈추는 것은 정상이다. 브라우저는 HTTP/1.1에서 호스트당 커넥션을 6개로 제한하므로, 나머지는 앞 요청이 끝난 뒤에 도착해 이미 잡힌 좌석을 만난다. 서버의 한계가 아니라 브라우저의 한계다 — 같은 실험을 스크립트로 20개 동시에 보내면 none에서 20건이 홀드된다.
전략을 바꾸려면 앱을 다시 띄워야 한다(약 13초). 전략 빈은 기동 시 하나만 만들어져 SeatHoldService에 직접 주입되므로, 런타임 교체는 측정 경로인 그 클래스를 고치는 일이 된다. 시연 편의로 M3가 잰 코드를 건드리지 않는다.
./holdfast strategy pessimistic
이 화면은 전환을 감지해서 위 배지를 자동으로 갱신한다. 터미널에서 명령을 붙여넣고 이 창을 그대로 두면 된다.

첫 실행은 한 번 눌러 버리고 시작하라. JVM이 데워지기 전 첫 묶음은 일부 요청이 연결 단계에서 실패한다.
