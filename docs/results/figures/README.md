# 발표용 그림

**60회 측정을 발표 자료에 넣을 형태로 다시 말한 것이다.** 새로 잰 것이 없다 —
값은 전부 아래 표가 가리키는 자리에서 왔다.

## 구성

```
m3-oversell-by-contention.svg   초과 확정 × 경합도 — 정합성 결론
m3-p95-by-contention.svg        p95 × 경합도 + 잡음 폭 — 성능으로는 못 가른다
```

## 왜 만들었나

**3주차 발표에서 교수님이 *"표 하나로만 보여주지 말고 경합도에 따라 그래프로
보이면 좋겠다"*고 하셨다**(`#198`). 교수 피드백 셋의 인덱스는
[`submissions/README.md`](../../submissions/README.md)의 3주차 발표 절에 있다.

## 무엇을 그렸나

| 그림 | 보이는 것 |
|---|---|
| **초과 확정 × 경합도** | `none`의 V-1이 **저경합 0 → 고경합 5·4·3 → 극단 1·1·1**로 갈리고, **락 전략 넷은 36회가 전부 0**이다. 경합도 축에서만 보이는 값이며, 7.2가 3단계를 유지한 이유가 이것이다 |
| **p95 × 경합도** | 다섯 전략 15개 값이 **같은 폭 안에서 겹친다**. 맨 아랫줄은 전략을 바꾼 것이 아니라 **같은 조건(`none` 고경합)을 다섯 세션에서 잰 것**이다 |

**두 그림이 한 쌍이다.** 정합성은 갈리고 성능은 안 갈린다 — 그것이 M3의 결론
전부다(`m3-conclusion.md` 0절).

### 성능 그림은 순위를 읽는 그림이 아니다

**막대를 나란히 세우지 않았다.** 7.6의 p95를 막대로 세우면 비율 0.78~1.79가
차이처럼 보이는데, 7.7.1과 `m3-conclusion.md` 2.5가 **"세션 간 변동이 전략 간
차이보다 크다"**로 판정한 값이다.

**그래서 잡음을 주장하지 않고 그려 넣었다.** 맨 아랫줄의 다섯 점이 잡음이고,
음영 폭은 그 다섯 점이 만든 범위다 — **읽는 사람이 눈으로 비교한다.** `#171`이
*"조건 간 차이 2.60ms는 잡음 바닥 5.62ms의 46%"*로 판정한 것과 같은 규율이다.

**`none`은 위치로 갈라 두었다.** 대조군이자 유일하게 검수 기준을 위반하는 쪽이라
맨 윗줄에 놓고 배경을 깔았다 — 다섯에 제각각 색을 주면 그 구분이 사라진다.

## 값의 출처

**이 표는 숫자를 옮겨 적지 않는다. 어디서 왔는지만 가리킨다.**

| 값 | 정본 |
|---|---|
| p95 15개 (5전략 × 3경합도) | [`concurrency-spec.md`](../../concurrency-spec.md) 7.6의 경합도별 세 표 |
| 초과 확정 15개 | 같은 표의 **초과 확정** 열 — 3회 값을 병기한 그대로 |
| 대조군 재측정 5개 | [`m3-conclusion.md`](../m3-conclusion.md) 2.5 |
| 경합도 정의 (좌석 · VU) | [`concurrency-spec.md`](../../concurrency-spec.md) 7.2 |

## `m3-conclusion.md`에 싣지 않는다

**그 문서에는 이미 같은 값이 표로 있다**(1절 · 2.1 · 2.5). 그림을 그 옆에 두면
**같은 사실을 두 곳에서 지키게 되고**, `erd.md` 4절이 *"같은 사실을 두 곳에서
지키면 어긋난다"*로 금지한 형태다. 표는 고치기 쉽고 SVG는 조용히 안 고쳐진다.

**그림의 성격이 제출물과 같다.** `submissions/README.md`가 수업 제출물을 두고
*"판단을 새로 만드는 것이 아니라 이미 있는 판단을 수업이 요구한 형식으로 다시
말한 것"*이라 적었고, 이 그림도 그렇다. **정본 옆이 아니라 따로 둔다.**

> **다시 볼 조건 — 60회를 다시 재면.** 그때는 이 그림이 낡는다. 다만
> `concurrency-spec.md` 7.3이 하네스 한계를 *"재측정으로 해소하지 않는다"*로
> 확정했고 `m3-conclusion.md` 3.5가 2차 측정을 "하지 않는다"로 판정했으므로,
> **60회는 닫힌 데이터다.** 그 판정이 뒤집히면 이 줄이 이 그림을 가리킨다.

## 그리는 수단 — 손으로 쓴 SVG, 생성기를 두지 않는다

**의존성이 없다.** `tools/render-md.mjs`가 `npx marked`를 쓰지 않은 것과 같은
근거다 — *"사전 준비가 필요한 발표 도구는 그 준비를 잊었을 때 실패한다"*(`#147`).

**생성기 스크립트를 커밋하지 않는 이유는 따로 있다.** 스크립트와 SVG를 둘 다
두면 **두 벌이 생기고 한 벌만 낡는다** — `#196`이 `DEMO_TABS`에서 겪은 그
형태다. 위 조건대로 데이터가 닫혀 있으므로 **결과물 하나만 남긴다.**

**고쳐야 하면 SVG를 직접 고친다.** 좌표가 아니라 값이 바뀌는 경우라면 위의
「다시 볼 조건」에 해당하므로 그림을 다시 만드는 것이 맞다.

## 발표 자료에 넣는 법

**`.pptx`는 저장소 밖이다**(`submissions/README.md`). SVG를 그대로 삽입하면
되고, PowerPoint가 SVG를 못 받으면 브라우저에서 열어 PNG로 저장한다.

**배경을 흰색(`#fcfcfb`)으로 박아 두었다** — 슬라이드 배경이 무엇이든 글자가
읽히고, GitHub 다크 모드에서도 같은 그림이 나온다.

읽게 두지 않는다.
