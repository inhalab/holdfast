# 시연 시나리오 (초안)

> **이 문서는 제안이다.** 순서와 강조점은 발표 준비하면서 둘이 맞춘다.
> 아래는 "지금 구현된 것으로 무엇을 어떤 순서로 보일 수 있는가"를 적은 것이지,
> 합의된 발표 대본이 아니다.

## 0. 준비

```bash
./holdfast demo none                 # 기동 + 시드 + 주소 안내
```

**`none`으로 시작한다.** 1절이 "락이 없으면 깨진다"를 먼저 보이기 때문이다. 1절
끝에서 `pessimistic`으로 바꾸고, 2절부터는 그 상태로 간다.

**시연 중에 코드를 고쳤다면 `--build`를 붙인다.**

```bash
./holdfast demo none --build
```

또는 직접:

```bash
HOLDFAST_STRATEGY=none HOLD_TTL_SECONDS=300 docker compose up -d --build
docker compose exec -T db psql -U holdfast -d holdfast < infra/demo-seed.sql
```

**이 경로에는 점검이 없다.** `./holdfast`가 하는 두 가지 — 앱이 실제로 응답할
때까지 기다리는 것과 멈춘 컨테이너를 알리는 것 — 이 빠진다. 시연 직전에
`nginx`가 죽어 있으면 화면이 그냥 안 열린다(이슈 #128).

**TTL 300초가 시연의 전제다.** 기본값 10초는 부하 측정용 고정 변수라
(`concurrency-spec.md` 7.3) 설명하는 동안 선점이 풀린다. `./holdfast demo`가 이
값을 대신 넣어 준다.

**2절은 `pessimistic`에서 한다.** `none`은 만료된 홀드를 회수하지 않는 것이
베이스라인의 정의라(`erd.md` 4.1), 예약 한 바퀴를 도는 동안 좌석 상태가 어긋난다.

**탭은 `./holdfast demo`가 연다.** 시연 중 주소를 타이핑하지 않는다. 아래 셋을
이 순서로 열므로 **왼쪽부터 탭 1·2·3**이고, 이 문서가 부르는 번호와 같다.

| 탭 | 주소 | 쓰는 절 |
|---|---|---|
| 1 | <http://localhost:8080/> — 프로그램 목록. `/programs`도 같은 화면이다 | 2절 |
| 2 | <http://localhost:8080/demo/race> | **1절 — 여기서 시작한다** |
| 3 | <http://localhost:8080/admin/programs> | 3절 |

**대본도 함께 열린다.** `docs/demo-script.md`를 HTML로 만들어 띄운다 —
표와 코드 블록이 원문보다 훨씬 읽힌다. 렌더링은 의존성이 없어 네트워크가 없어도
된다(`tools/render-md.mjs`).

**여는 것이 기본이고 끄는 길이 있다.**

```bash
./holdfast demo none --no-open       # 주소만 출력한다
```

**열기에 실패해도 준비는 끝난다.** 브라우저를 여는 명령(`start`·`open`·
`xdg-open`)이 없거나 `node`가 없으면 그 사실을 알리고 주소·경로를 출력한 채
넘어간다. 편의 하나 때문에 준비 명령이 멈추지는 않는다.

**전략만 바꿀 때는 `./holdfast strategy`를 쓴다** — `demo`를 다시 부르면 탭이
세 개씩 늘어난다.

### 0.1 어디서 도는가 — 집 PC에서 돌고 발표장에서 터널로 붙는다

**서버는 발표장에 없다.** 라이브 시연은 **집 PC의 Docker Compose**에서 돌고,
발표장에서는 브라우저로 **`https://demo.inhalab.cloud`**에 붙는다. 판정과 근거는
[`infra-decision.md`](infra-decision.md) 2.1에 있다.

| | |
|---|---|
| **서버** | 집 PC의 Docker Compose. **원격으로 켤 수 있게 해 둔다** |
| **발표자** | 발표장(학교)에서 브라우저로 `demo.inhalab.cloud` |
| **청중** | **붙지 않는다.** 화면을 본다 |

**AWS는 `app.inhalab.cloud`에 실제 서비스로 띄워 한 번 보인다** — 배포 증거다.
라이브는 아니므로 **당일 AWS가 안 떠도 발표가 된다.**

#### 시작하기 전에 — 집 PC부터 깨운다. 그리고 셸이 필요하다

**PC를 가져가지 않으므로 서버가 꺼져 있으면 아무것도 안 된다.** 발표장에 도착해서
`./holdfast demo`를 치기 전에 **집 PC를 원격으로 켜고 터널이 붙었는지 확인한다.**

> **브라우저만으로는 부족하다.** 이 대본은 터미널을 두 번 쓴다 — 0절의
> `./holdfast demo`와 **1절 끝의 `./holdfast strategy pessimistic`**이다.
> `scope-m4.md` 8절이 *"전략 전환은 터미널에 남는다"*로 판정한 그 한 줄이고,
> **그 터미널이 집 PC의 셸이어야 한다.**
>
> **집 PC를 원격으로 켜는 수단이 셸도 함께 주는지 확인한다.** 안 주면 전략
> 전환을 발표장에서 할 수 없고, 그때는 **1절을 `none`으로 끝내고 2절부터를 미리
> `pessimistic`으로 띄워 두는 것**과 **전환을 브라우저로 옮기는 것**(8절이 한 번
> 기각한 판단) 중에 다시 정해야 한다. **여기서 정하지 않는다.**

#### 이 절은 두 번 뒤집혔다

| 한때 적었던 것 | 지금 |
|---|---|
| *"청중이 Cloudflare Tunnel로 붙는다"* (#172) | **청중은 붙지 않는다.** 터널은 남지만 **이유가 다르다** |
| *"주소는 `http://localhost:8080` 하나다"* · *"네트워크를 지나지 않으므로 발표장 사정에 흔들리지 않는다"* (#176) | **회수한다.** 서버가 집에 있고 발표자가 발표장에 있으므로 **그 사이에 네트워크가 있다.** `localhost`는 성립하지 않는다 |

**터널이 있는 이유는 청중 참여가 아니라 발표자 본인이 집 PC 화면에 닿아야
하기 때문이다.**

#### 안 되면 두 단계로 물러선다

**의존이 늘었으므로 물러설 곳을 미리 정한다.**

| | 무엇 | 잃는 것 |
|---|---|---|
| 1 | **터널** — `demo.inhalab.cloud` | — |
| 2 | **원격 데스크톱**으로 집 PC 화면을 띄운다 | 청중이 보는 것이 **중계 영상**이 된다. 화면 전송 지연·프레임 드롭으로 **발사 장면이 뭉개질 수 있다** |
| 3 | **녹화** | `scope-m4.md`가 뺀 그것이다 — **보는 사람이 확인할 수 있는 것이 사라진다.** 마지막 수단이다 |

**2번을 주 수단으로 고르지 않은 근거는 `infra-decision.md` 2.1에 있다.**

#### 수를 말하지 않는다

**터널을 지나므로 동시 도착이 6이 아니고, 얼마인지도 모른다** — 두 번 재서
1차 19~20, 2차 86·80으로 갈렸다(2.1의 표). **값이 흔들리는 문제는 남아 있고,
대응은 대본에 수를 안 적는 것이다.**

**"동시에 200개를 쐈습니다"라고 말하지 않는다.** 세지 않아도 되는 말로 한다.

> 브라우저는 한 번에 다 보내지 않습니다. 그래서 좌석 하나에 몰아쳐 **겹치게**
> 만듭니다. **진짜 동시성 숫자는 뒤에 나올 k6 500 VU에 있습니다.**

**시연의 일은 증거가 아니라 예시다.** 동시성의 증거는 k6 27회(500 VU)이고
이미 나와 있다. 문안은 **#170이 다룬다.**

## 1. 문제 — 락이 없으면 깨진다 (3분)

**여기서 시작한다.** 이 프로젝트의 산출물은 예약 화면이 아니라 동시성 증거이므로,
기능 소개보다 문제를 먼저 보인다.

**탭 2 — `/demo/race`**

1. `none` 전략으로 "동시에 홀드 요청" — 활성 홀드가 여러 건 남는다(초과 홀드)
2. **좌석 수를 1로 둔 채로 한다.** 브라우저는 호스트당 커넥션이 6개라, 좌석이
   6개 이상이면 동시에 뜬 요청이 서로 다른 좌석으로 갈라져 **`none`도 초과 홀드를
   내지 않는다**(`scope-m4.md` 7절의 실측 표). 화면이 이 조건을 계산해 경고한다
3. **손으로 두 창을 클릭하는 것으로는 이 장면을 만들 수 없다**는 점을 말한다.
   홀드 트랜잭션이 밀리초라 사람이 누른 두 요청은 겹치지 않는다. 그래서 브라우저가
   `Promise.all`로 한 번에 발사한다
4. **전략을 바꾼다 — 화면이 아니라 터미널에서 한다.** 화면의 `명령 복사`를 누르고
   터미널에 붙여넣는다.

   ```bash
   ./holdfast strategy pessimistic
   ```

   **앱 재기동이라 약 13초 걸린다.** 그 창을 그대로 두면 화면이 전환을 감지해
   상단 배지를 스스로 갱신하므로, 붙여넣은 뒤 터미널을 다시 볼 일이 없다
5. 다시 발사 — 좌석마다 1건이고 나머지는 409다

**13초에 할 말이 있다.** 그 사이에 일어나는 일이 곧 설명거리다 — 앱만 다시 뜨는
것이 아니라 **부분 유니크 인덱스 U-2를 지우거나 다시 만든다.** `none`은 U-2가
빠져야 비로소 `none`이기 때문이다(`erd.md` 3.1). **전략은 앱 안에만 있는 것이
아니다**가 이 프로젝트 결론과 그대로 붙는 이야기다.

> **화면에서 전략을 바꾸지 않는 이유**는 `scope-m4.md` 8절에 있다. 런타임 교체는
> 측정 경로인 `SeatHoldService`를 고치는 일이고, 위임 프록시로 그것을 피해도
> U-2가 스키마에 있어 `none`이 `unique`처럼 동작한다. 네 가지 경로를 전부 따져
> 보고 하지 않기로 했다 — 질문이 나오면 이 대목이 답이다.

**이어서 README의 측정 표를 띄운다.** 화면에서 본 것이 60회 측정에서 같은 모양으로
나온다는 것 — 락 없음만 초과 확정 4석, 네 전략은 전부 0.

**질문이 나올 만한 곳**

- "성능 차이는?" → **없다고 말하지 않는다.** p95가 다섯 전략 모두 18~41ms인데
  같은 `none` 대조군도 세션마다 18~41ms로 흔들린다. "차이가 없다"가 아니라
  **"이 지표로는 볼 수 없다"**가 우리가 말할 수 있는 전부다(M3 결론 2.5)
- "M4에서 뒤집혔다던데?" → Outbox가 임계 구역을 늘려 `pessimistic`이 27% 느려
  보였고 "이제 구분된다"고 적었다가, `none`을 여섯 번 재 보니 그 값이 2.28배
  흔들려 판정을 회수했다. 폐기 기록 C절에 남겼다

## 2. 흐름 — 예약 한 바퀴 (4분)

**탭 1 — `/programs`**

```
프로그램 목록 → 회차 목록 → 좌석 선택 → 선점 → 결제 → QR → 검표
```

1. **회차 목록**에서 상태 표시를 짚는다 — 매진·접수 종료·오픈 전을 **감추지 않고
   적는다**(`design-spec` 5.6). 지우면 "원래 없었는지 이미 끝났는지"를 구분할 수 없다
2. **좌석맵**에서 좌석을 고르고 선점. 남은 시간이 카운트다운된다
3. **결제** → 예약 확인 화면으로 이동, QR 토큰이 나온다.
   **`?userId=`를 바꿔도 끝까지 돈다.** 좌석맵이 연 주소의 userId로 예약을 넣고
   (`X-User-Id`), 결제 뒤 예약 확인으로 보낼 때 같은 값을 싣는다. 예약 확인은
   소유자만 볼 수 있으므로(`scope-m4.md` 8절) 그 값이 있어야 열린다 —
   **#126 이전에는 빠져서 사용자 2가 여기서 404를 만났다**
4. **검표**(하단 링크)에 그 토큰을 붙여넣는다 → `ADMITTED`
5. **한 번 더 붙여넣는다** → `REJECTED_DUPLICATE`. 여기가 이 화면의 요점이다

**화면 바닥의 인스턴스 배지를 짚는다.** 새로고침하면 `app1`/`app2`가 번갈아 찍힌다 —
앱 2대가 nginx 뒤에 있다는 구성도의 문장이 화면으로 확인되는 자리다.

## 3. 운영 — SQL 없이 만든다 (3분)

**탭 3 — `/admin/programs`**

발주처 관점에서 "운영할 수 있는 시스템"인지를 보이는 부분이다.

1. **좌석배치도** — 구역을 이름·행·열 셋으로 만든다. 격자 미리보기가 사용자
   좌석맵과 같은 규칙으로 그려진다
2. **프로그램·회차 등록** — 회차를 만들면 좌석재고와 할당량 행이 함께 생긴다.
   **좌석재고를 미리 만드는 것이 좌석 단위 락의 전제다**
3. 그 회차를 사용자 화면에서 연다 — 방금 만든 것이 바로 팔린다.
   **다만 여기서 열린 좌석맵으로는 동시성을 보일 수 없다.** 관리자 회차 목록의
   `좌석맵 →`은 `?userId=`를 싣지 않아 **항상 사용자 1로 열린다**
   (`scope-m4.md` 8절 표). 그런데 "같은 좌석을 여럿이 동시에 노린다"는 창마다
   userId가 달라야 성립한다(6절). 보여야 한다면 둘 중 하나다.

   - 주소창에서 `?userId=2`를 붙여 창을 하나 더 연다. **사용자 화면 안에서는 그
     값이 유지된다** — 좌석맵 ↔ 회차 목록을 오가도 2로 남는다(#126)
   - **그냥 1절의 `/demo/race`에서 한다** — 그쪽이 이 시연의 자리이고, 손으로
     두 창을 클릭해서는 애초에 겹치지 않는다는 것도 거기서 이미 말했다

**여기서 삭제 정책을 한 문장으로 말한다.** 회차가 배치도를 참조하기 시작하면
구역·좌석을 더하거나 지울 수 없다. 좌석을 지우면 판매 중인 회차의 좌석맵에서
좌석이 사라지기 때문이다.

## 4. 안 한 것 (1분)

**질문받기 전에 먼저 말하는 편이 낫다.**

| 없는 것 | 왜 |
|---|---|
| 인증·권한 | `X-User-Id` 헤더가 대신한다. 관리자 경로를 누구나 연다 — **배포하면 그 경로를 끄기로 정했다**(`infra-decision.md` 3.1) |
| 실제 PG·알림 발송 | Mock. 상태 전이와 재시도·중복 방지는 구현했다 |
| AWS 배포 | 로컬 Docker Compose로 앱 2대 구성을 재현했다(#42 보류) |
| UI 표준화 | `design-spec` 5.3 — 좌석맵에 시간을 쏟지 않는다고 처음에 정했다 |
| 정산·통계 | 금액이 0이라 의미가 없다 |

범위를 어떻게 잘랐는지는 [`rfp-scope.md`](rfp-scope.md)에 RFP 원문과 나란히 적혀 있다.

## 시간이 부족하면

**1절만 한다.** 이 프로젝트에서 다른 팀과 갈리는 지점은 예약 기능이 아니라
"락 없이 깨지는 것을 재현하고 네 전략으로 없앤 뒤 비교 측정했다"이고,
그 장면이 `/demo/race` 하나에 들어 있다.
