# 배포 환경 결정 (#8)

`docs/concurrency-spec.md` 0.3절이 박태준에게 M1 기한으로 지정한 결정 항목이다.
AWS를 쓸지, 쓴다면 어떤 형태로 할지를 여기서 고정한다.

## 결론 요약

| 항목 | 결정 |
|---|---|
| 측정 주력 | **로컬 Docker Compose** (통제된 환경, 재현성 우선) |
| **라이브 시연** | **집 PC의 Docker Compose → Cloudflare Tunnel → `demo.inhalab.cloud`** (2.1). 발표장에서 브라우저로 붙는다 |

| 우선순위 | 로컬·측정이 먼저. AWS 배포는 여유가 생기면 진행 |
| DB·캐시 버전 | RDS PostgreSQL 18 / ElastiCache Redis 7 (로컬과 일치) |

## 1. 판단 기준 (#8 이슈)

세 가지 기준으로 판단했다.

- **다중 인스턴스 2대 + 공유 Redis 구성이 가능한가** — 로컬에서 이미 구현·검증 완료(앱 2대 + nginx + Redis, k6 부하 테스트 통과).
- **4개월간 비용이 감당 가능한가** — 아래 2절.
- **부하 테스트 결과의 재현성이 확보되는가** — 로컬이 통제된 환경이라 재현성이 더 높다.

## 2. 측정은 로컬에서 한다

부하 테스트만 놓고 보면 로컬/온프레미스가 통제된 환경이라 측정이 더 깔끔하다.
네트워크 변수가 끼지 않고, 반복 실행이 자유롭고, 비용이 들지 않는다. 설계서
7.3의 고정 변수 표(커넥션 풀·스레드 풀·격리 수준 등)를 로컬에서 완전히 통제할
수 있다.

**AWS는 "측정을 더 잘하려고"가 아니라 "클라우드에 실제 배포도 했다"를 보이는
별개 목적으로 선택한다.** 락 전략 비교표의 숫자는 로컬에서 뽑는다.

**이 원칙이 AWS에서 구체적으로 무엇을 뜻하는지는 3.3에 있다** — 클라우드에서
k6를 돌리더라도 스모크이고, 정본을 갱신하지 않는다. `concurrency-spec` 7.3이
재측정 약속을 회수한 것과 같은 판정이다.

### 2.1 시연은 집 PC에서 돌고 발표장에서 터널로 붙는다

**먼저 전제를 적는다. 이 절이 두 번 뒤집힌 이유가 이것이 안 적혀 있었기
때문이다.**

| | 사실 |
|---|---|
| **서버가 어디 있나** | **집 PC의 Docker Compose.** 원격으로 켤 수 있게 해 둔다 |
| **발표자가 어디 있나** | **발표장(학교).** **PC를 가져가지 않는다** |
| **화면을 어떻게 보나** | 발표장 브라우저 → **Cloudflare Tunnel** → 집 PC |

**결론: 라이브 시연(`demo-script.md` 1절)은 집 PC의 Docker Compose에서 돌고,
발표장에서 `demo.inhalab.cloud`로 붙는다. AWS는 `app.inhalab.cloud`에 실제 서비스로
띄워 "클라우드에 배포했다"를 보인다.** 이슈 #172의 판정이며 **두 번 뒤집혔다** —
아래에 회수를 적는다.

| | 어디서 도나 | 무엇을 위해 |
|---|---|---|
| **시연** (대본 1절 라이브) | **집 PC의 Docker Compose** → Cloudflare Tunnel → **`demo.inhalab.cloud`** | 발표자가 발표장에서 화면을 띄운다 |
| **배포** | AWS Fargate → ALB → Cloudflare → **`app.inhalab.cloud`** | **배포 증거이자 실제 서비스.** 없으면 슬라이드로 대체 가능 |

**환경이 셋이다** — 로컬 측정 · 집 PC 시연 · AWS 배포. **앞의 둘은 같은 기계이고
같은 `docker compose`**이며 다른 것은 **전략과 프로퍼티뿐**이다. 갈리는 것은
**누가 어디서 그 화면에 닿는가**다 — 측정은 그 기계 앞에서, 시연은 발표장에서.

#### 왜 집 PC인가 — 근거 둘

- **2절이 이미 #42의 목적을 좁혀 놨다** — *"AWS는 '측정을 더 잘하려고'가 아니라
  '클라우드에 실제 배포도 했다'를 보이는 별개 목적으로 선택한다."* **그 목적에는
  라이브 시연이 필요 없다.**
- **발표 당일 AWS가 안 떠도 발표가 된다.** #42가 *"없으면 안 되는 것"*에서
  *"있으면 좋은 것"*으로 내려간다. 4절이 AWS를 "잘라도 되는 것"으로 본 것과 같은
  방향이고, 이제 **자를 때 잃는 것이 슬라이드 한 장**이다.

#### 왜 터널인가 — 청중 참여 때문이 아니다

**발표자 본인이 발표장에서 집 PC의 화면에 닿아야 하기 때문이다.** 서버가 집에
있고 PC를 가져가지 않으므로 **`localhost`는 그 조건에서 성립하지 않는다.**

**이것이 한때 적었던 이유와 다르다.** #172가 처음 터널을 넣은 이유는 *"청중이 자기
폰으로 붙는다"*였고 #176이 그것을 뺐다. **청중 참여를 되살리지 않는다** — 아래
"딸려 살아나지 않는 것"을 보라. 터널은 이제 **접근 수단**이지 시연 장치가 아니다.

#### 원격 데스크톱을 주 수단으로 고르지 않았다

**검토하고 뺀 것과 검토한 적 없는 것은 다르다.** 집 PC 화면을 발표장으로 중계하는
방법도 `localhost`를 살린다. 그래도 터널을 고른 근거가 셋이다.

- **청중이 보는 것이 화면을 중계한 영상이 된다.** `scope-m4.md`가 녹화를 뺀 근거가
  *"보는 사람이 확인할 수 있는 것이 화면 안에서 사라진다"*였는데, 중계 영상은
  **녹화와 구분이 안 간다.** 터널이면 **발표장 브라우저가 실제로 요청을 보내고
  받는다**
- **새 변수가 더 크다** — 화면 전송 지연·해상도·프레임 드롭. **200발 쏘는 장면이
  뭉개지면 시연이 안 보인다.** 터널은 HTTP 왕복만 지난다
- **터널은 두 번 재서 성질을 안다**(#170, 아래 표). **원격 데스크톱 지연은 재지
  않았다**

**다만 fallback으로는 둔다** — 터널 실패 시 원격 데스크톱, 그것도 안 되면 녹화.
세 단계는 `demo-script.md` 0.1에 있다.

#### 회수 — 두 번 뒤집힌 자리다. 무엇이 남고 무엇이 빠지는지 나눈다

**이 절은 한때 이렇게 적었다**(#172·#175).

> 라이브 시연은 개발 PC의 Docker Compose에서 돌고, **청중은 Cloudflare Tunnel로
> 붙는다.**

**#176이 그것을 `localhost` 직접 접속으로 되돌렸다.** 근거는 재현성이었고, 그
근거는 터널을 실제로 재서 나왔다(#170·#172, 아래 표).

> **#176의 되돌림을 다시 회수한다.** 그 판정은 **전제가 적히지 않은 채 세워졌다** —
> *"발표자가 개발 PC 앞에 있다"*를 어디에도 적지 않고 그 위에 근거를 얹었다.
> **실제 전제는 다르다**(위 표) — 서버는 집 PC에 있고 발표자는 발표장에 있다.
> **`localhost`가 그 조건에서 성립하지 않는다.**
>
> **#176이 옳게 짚은 것은 그대로 둔다.** 아래 셋은 터널이 돌아와도 유효하다 —
> **동시성의 증거는 k6 27회이고 브라우저 시연의 일은 증거가 아니라 예시다** ·
> **대본에 배수를 적지 않는다** · **아래 관측표 전부.** 되살아나는 것은
> **경로**이지 청중 참여가 아니다.

`/proc/net/tcp`를 0.05초 간격으로 표집해 쟀다.

`/proc/net/tcp`를 0.05초 간격으로 표집해 쟀다.

| | 관측 |
|---|---|
| **브라우저 6커넥션 제약** | **실재한다.** 로컬 직접 200발에 동시 도착 **6**, 40초 무변동. **화면 코드에 상한이 없는데도** 그렇다 |
| **터널을 쓰면** | **6이 아니게 된다.** 다만 **얼마가 되는지를 통제하지 못한다** — 같은 조건에서 1차 19~20, 2차 86·80으로 **4.5배 갈렸다** |
| **요청 수** | **결정 변수가 아니다.** 200→800으로 4배에 12%만 움직였다 |
| **`cloudflared` → nginx** | **60 미만의 동시 커넥션 상한은 관측되지 않았다.** 60을 넘는 지점은 재지 않았다 |
| **처리량** | **터널이 4배 느리다** — 직접 약 8,300 req/s ↔ 터널 약 2,080 req/s. 대가는 커넥션 수가 아니라 **왕복 지연**이다 |

**무엇이 막는지는 모른다.** 화면(코드에 상한 없음) · `cloudflared`(위 60) ·
엣지 설정(무료 플랜 `SETTINGS_MAX_CONCURRENT_STREAMS`가 문서상 **200**)이 소거됐고,
남는 후보는 브라우저↔엣지 구간이다.

**#176이 이 표로 세운 근거 셋 중 둘은 남고 하나는 무너진다.**

| #176의 근거 | 지금 |
|---|---|
| **발표에서 숫자를 말할 수 없다** — 같은 조건에 4.5배가 갈리면 리허설 값이 발표장에서 안 나온다 | **남는다.** 값이 흔들리는 문제는 **해결되지 않았다.** 대응은 터널을 빼는 것이 아니라 **대본에 배수를 적지 않는 것**이다(0.1) |
| **청중 참여가 증거를 더하지 않는다** — 증거는 k6 27회(500 VU)이고 브라우저 시연의 일은 **증거가 아니라 예시**다 | **남는다.** 그래서 **청중 참여는 되살리지 않는다** |
| ~~**의존성이 줄지 않고 는다** — 로컬은 아무것에도 안 기대는데 터널은 발표장 네트워크와 Cloudflare 엣지에 건다~~ | **무너진다.** **집 PC 구동도 발표장 네트워크에 기댄다.** *"로컬은 아무것에도 안 기대지 않는다"* — 그 비교의 한쪽이 존재하지 않았다 |

**세 번째가 무너지는 것이 이 회수의 핵심이다.** 터널이 의존을 *더하는* 것이
아니라, **어느 쪽을 골라도 발표장 네트워크에 기댄다.** 남는 선택은 *"의존을
질 것인가"*가 아니라 **"어떤 의존을 질 것인가"**다 — 그래서 위에서 원격
데스크톱과 비교했다.

**측정은 지우지 않고 남긴다.** *"검토했고 이 조건에서 뺀다"*가 *"검토한 적
없다"*보다 강하다 — `erd.md` 4.1이 쓰는 방식이다. **값이 흔들리는 문제는 여전히
남아 있고**(1차 19~20, 2차 86·80), 조건이 바뀌면(예: 발표장 네트워크를 미리 잴
수 있게 되면) 이 표부터 다시 본다.

#### 딸려 살아나는 것 둘 — `admin` ingress와 #174

**#176은 터널을 빼면서 둘을 함께 회수했다.** 터널이 돌아오므로 **둘 다 살아난다.**
회수 사유가 *"`localhost`는 노출되지 않는다"*였는데 **집 PC가 터널로 인터넷에
나가므로 그 사유가 없다.**

**`admin`은 프로퍼티로 못 가른다.** `holdfast.admin.enabled`는 **서버 단위**라
켜면 터널에도 열리고 끄면 발표자도 못 쓰는데, **`demo-script.md` 3절이 통째로
`/admin/programs`다.** #124의 관용구는 *"배포하면 없앤다"*였고 여기서 필요한 것은
**"발표자는 쓰고 청중은 못 쓴다"**라 축이 다르다.

**그래서 프로퍼티는 켜 두고 터널 ingress가 경로를 가른다.**

```
청중·외부  demo.inhalab.cloud  → 아래 허용 목록만
발표자     터널 주소 그대로     → 대본이 쓰는 경로 전부
```

> **발표자도 터널을 지난다는 것이 #172 때와 다르다.** 그때는 발표자가 개발 PC
> 앞에 있어 `localhost`로 전부 열렸다. 지금은 발표장에 있으므로 **`/admin`도 터널을
> 지나야 한다.** 그러면 ingress가 `/admin/**`을 실어야 하고, **청중과 발표자를
> 경로로 가를 수 없다** — 둘이 같은 호스트명으로 들어온다.
>
> **이 갈래는 여기서 닫지 않는다.** 수단이 셋 보인다 — 호스트명을 둘로 나누거나
> (`admin.` 서브도메인), Cloudflare Access를 `/admin/**`에 걸거나, **3절 동안만
> ingress를 바꾸거나**다. **`infra/`를 건드리는 판단이라 #174가 진다.**

회차가 바로 팔린다"*인데 **같은 DB라야 보인다.** 2절이 `pessimistic`에서 도므로
관리자도 그쪽이다.

**`cloudflared`의 ingress 설정 파일은 이 표의 구현이지 정본이 아니다.** 설정에만
있으면 **"왜 이 경로만 열었나"가 남지 않는다.** `erd.md` 4절이 U-2를 두고 적은
*"같은 사실을 두 곳에서 지키면 어긋난다"*와 같은 형태로, **정본은 이 표 하나**다.

#### Access를 세 호스트명 모두에 건다 — 대가가 그만큼 줄어든다

**#174가 `/admin`에 Access를 걸기로 하면서 호스트명 분리를 기각했다.**

> **호스트명을 나누는 것은 접근 제어가 아니다.** 추측 가능하고, 인증서 투명성
> 로그에 실린다. **주소를 아는 사람만 온다는 전제가 성립하지 않는다.**

**그 논거가 `demo-none`·`demo-pess`에도 그대로 걸린다.** 좌석맵과 `/demo/race`도
같은 방식으로 노출된다 — 다른 점은 거기서 할 수 있는 일이 덜 위험하다는 것뿐이고,
`/demo/race/reset`은 한 회차의 좌석·홀드·예약을 지운다.

**그리고 붙는 사람이 발표자 하나다**(`demo-script.md` 0.1 — 청중은 붙지 않는다).
**셋 다 거는 데 잃는 것이 없다.**

| | 세션 |
|---|---|
| 발표자 | 발표 전에 **발표장에서 쓸 브라우저로** 한 번 인증. 수명 1주 |
| 그 외 | 앱에 닿지 않는다 |

#### 이 안의 대가 — ingress 설정이 곧 보안 경계다

> **위의 Access가 이 대가를 줄인다.** 아래는 Access를 걸기 전의 서술이고,
> 셋 다 걸린 지금 ingress는 **유일한 경계가 아니라 한 겹 더**다. 그래도
> 지운다면 잘못 열렸을 때 무엇이 나가는지가 안 남으므로 그대로 둔다.

**앱이 막으면 틀려도 404인데, ingress는 틀리면 열린다.** 게다가 **발표자는 자기
PC에서도 볼 수 있으므로 정상으로 보인다.** 프로퍼티와 달리 앱이 막아 주지 않는
것이 이 선택의 값이자 대가다.

**그래서 확인 절차를 대본이 아니라 `holdfast` 스크립트에 둔다** — 터널을 띄운 직후
그 주소로 `/admin/programs`를 쳐서 **404가 아니면 멈춘다.** 대본에 두면 사람이
빠뜨린다(**#132가 `warn_stopped`를 경고가 아니라 중단으로 만든 것과 같은 자리**).
**#174가 그것을 진다 — #176이 닫았던 것을 다시 열었다.**

| | 전략 | `holdfast.demo.enabled` | `holdfast.admin.enabled` |
|---|---|---|---|
| 개발·측정 | 다섯 교체 | 켬 | 켬 |
| **시연** | `none` ↔ `pessimistic` | 켬 | **켬** — 경로는 **터널 ingress가 가른다**(위) |
| 배포 | `pessimistic` 고정 | 끔 | 끔 (3.1) |

**이미지를 나누지 않는다.** `concurrency-spec` 4절의 *"전략 밖 코드에 전략별 분기를
넣지 않는다"*와 같은 이유다 — 이미지가 둘이면 그보다 큰 분기가 생기고, **#143이 겪은
"테스트는 도는데 컨테이너에서만 안 뜬다"가 이미지 단위로 재현된다.** 필요한 분리는
이미 다 있다: `@ConditionalOnProperty`(전략 다섯)와 #124가 만든 프로퍼티 둘.

#### 수를 말하지 않는다 — 대본이 그것을 정직하게 말한다

**터널이므로 동시 도착이 6이 아니다. 그리고 얼마인지 모른다** — 위 표가 1차
19~20, 2차 86·80으로 갈렸다. **#176이 "6이다"로 적었던 것은 `localhost` 전제
위에서였고, 그 전제가 회수됐다.**

**그래서 대본은 수를 말하지 않는다.** *"동시에 200개를 쐈다"*도 *"6중 경합"*도
말하지 않는다 — **앞의 것은 브라우저가 그렇게 보내지 않아 부정확하고, 뒤의 것은
터널에서 6이 아니라 부정확하다.**

**대신 성질을 말한다.** 브라우저가 한꺼번에 던지지 않으므로 **좌석 하나에 몰아쳐
경합을 만드는 것**이고, **진짜 동시성 숫자는 k6 500 VU에 있다.** 이것이 #176이
옳게 짚은 대목이고 터널이 돌아와도 그대로다 — **브라우저 시연의 일은 증거가
아니라 예시다.** `scope-m4.md` 7절이 이 제약과 우회를 이미 적어 두었다. 대본
문안은 #170이 다룬다.

#### AWS는 실제 서비스로 연다

**시연이 AWS에 없다고 해서 AWS가 죽은 화면인 것은 아니다.** 도메인을 붙여
**실제로 도는 서비스**로 띄운다 — 그것이 "배포했다"의 가장 짧은 증거다.

- **Cloudflare를 프록시로 둔다.** 무료 플랜이 엣지에서 TLS와 HTTP/2를 주므로
  **ACM 인증서도 CloudFront도 필요 없다**(3.2 회수)
- **오리진 구간을 평문으로 두지 않는다.** ALB 보안그룹을 **Cloudflare IP 대역으로
  좁힌다** — 인증서를 하나 더 관리하지 않고 오리진을 가리는 실용적인 답이다
- **노출 스위치 셋은 이미 있다** — `admin` 끔·`demo` 끔(위 표), ALB에서
  `/actuator/*` 거부(3.1)
- **`/api/**`는 인증이 없어 누구나 홀드를 잡을 수 있다.** `rfp-scope.md` 4.3이
  인증을 배제한 결과이며 **여기서 바꾸지 않는다.** 감수하는 대신 **발표 직후
  `terraform destroy`**로 창을 닫는다(5절)

#### 도메인 — `inhalab.cloud`. 서브도메인 둘로 나눈다

**확보했다.** Cloudflare 네임서버 이전도 끝나 **Active**다. 이 문서가 한때
`<도메인>`으로 두었던 자리가 이것이다.

| 이름 | 어디로 | 무엇 |
|---|---|---|
| **`demo.inhalab.cloud`** | Cloudflare Tunnel → **집 PC** | 라이브 시연 |
| **`app.inhalab.cloud`** | Cloudflare → ALB → **AWS Fargate** | 배포 증거 |

**하나로 돌려 쓰지 않는다.** 근거가 셋이다.

- **수명이 다르다.** AWS는 `terraform destroy`로 발표 직후 내리고(5절) 터널은 그
  전에 닫는다. **하나에 물려 두면 내리는 순서가 곧 DNS 변경**이 되고, 전파를
  기다리는 동안 발표가 멈춘다
- **가리키는 곳이 다르다.** 터널은 `CNAME`이 터널 id로 가고 ALB는 Cloudflare
  프록시를 지난다. **한 이름에 둘을 번갈아 붙이면 어느 쪽이 떠 있는지가 DNS에
  가려진다**
- **대본이 주소를 적는다.** `demo-script.md`가 여는 주소를 적어 두는데, **같은
  이름이 때에 따라 다른 것을 가리키면 대본이 무엇을 여는지 말하지 못한다**

**용도가 한 번 뒤집혔다.** 3.2의 회수 블록이 도메인을 *"터널 주소용이고 ALB용이
아니다"*라고 적었다가 #176이 *"AWS 서비스 주소용"*으로 뒤집었는데, **지금은
둘 다다** — 서브도메인이 갈라 준다.

## 3. AWS 형태 — ECS Fargate

EC2와 Fargate를 비교했다.

| | EC2 | ECS Fargate |
|---|---|---|
| 데모 1회 비용 | ~$1 | ~$1–2 |
| 월 방치 시 | $70–80 | $120–130 (+ NAT $45) |
| 설정 공수 | 낮음 (compose 그대로) | 높음 (태스크 정의·서비스·네트워킹) |
| 클라우드 경험·발표 임팩트 | 보통 | 높음 |

**Fargate를 택한 이유는 서버리스 컨테이너 오케스트레이션 경험이다.** 측정
품질에는 EC2와 차이가 없으므로, 이 선택의 근거는 전적으로 학습·발표 가치에
있다. 데모는 잠깐 띄우고 즉시 내리는 방식이라 1회 비용 차이는 무시할 수준이다.

Fargate 단가(2026, Linux/x86): vCPU 시간당 $0.04048, 메모리 GB당 시간당
$0.004445. 앱 2대(각 1 vCPU / 2 GB) + ALB + RDS(db.t3.micro) + ElastiCache
(t3.micro) 기준 시간당 약 $0.17. 반나절 데모 약 $1, 하루 약 $2.

### 3.1 배포하면 `/admin/**`을 끈다 — 잠그는 것이 아니라 없앤다

**결론: `holdfast.admin.enabled` 프로퍼티로 끈다. 로컬은 켬(기본값), 배포는
끔.** 이슈 #124의 판단 항목이며 여기서 확정한다.

### 무엇이 문제인가

`/admin/**`은 **누구나 연다.** 인증이 없기 때문이고, 그 사실은
`scope-m4.md` 8절·`rfp-scope.md` 3장·`demo-script.md` 4절에 이미 적혀 있다.
**이 절을 쓸 당시에는 로컬 Docker Compose에서만 도므로 노출이 없었다**(2절).
그런데 #42로 ALB 뒤에 뜨면 **관리자 화면이 열린 채 인터넷에 나간다.**

> **이 전제는 로컬에서 유효하다 — 한 번 흔들렸다가 돌아왔다.** 2.1이 시연을
> 개발 PC + Cloudflare Tunnel로 정했을 때는 *"로컬은 노출이 없다"*가 터널을 여는
> 동안 거짓이었고, 그래서 **`admin`을 터널 ingress로 가르는 안**과 **#156을 그
> 앞에 두는 순서**가 생겼다. **2.1이 터널을 회수하면서 둘 다 사라졌다** —
> 시연도 `localhost`라 노출이 없다. 아래 판정(배포하면 끈다)은 처음부터
> 그대로다.

### 네 선택지와 판정

| 수단 | 측정 경로 | 판정 |
|---|---|---|
| **(a) `holdfast.admin.enabled` 프로퍼티** | 안 닿는다 — 빈을 아예 안 만든다 | **채택** |
| (b) nginx `auth_basic` | 안 닿는다 — k6는 `/api/*`만 친다 | **기각 — 아래** |
| (c) Spring Security를 `/admin/**`에만 | **닿는다** — 필터 체인이 `/api/holds`도 지난다 | **기각** |
| (d) 하지 않는다 | — | **기각** |

**(c)를 먼저 뺀다.** 필터 체인은 경로를 가리지 않고 모든 요청에 붙는다.
`concurrency-spec.md` 7.8이 **확정 트랜잭션에 INSERT 한 문장 늘어난 것을 세 번
재고도 판정하지 못했다** — 측정 경로에 무엇을 더할 때 드는 값이 그만큼이다.
그리고 #105가 곧 PER-002를 다시 잰다.

**(b)가 정반대인 이유가 이 판정의 핵심이다.** `nginx.conf` 첫 줄이 적어 두었다 —
**"AWS로 옮기면 이 역할을 ALB가 대신한다."** 즉 nginx는 **로컬에만 있다.**
`auth_basic`을 걸면 **노출이 없는 로컬에는 자물쇠가 걸리고, 노출이 있는 AWS에는
안 걸린다.** 거기에 비밀번호 파일이 하나 늘고, `nginx.conf`를 고치면 reload가
필요하다(`design-spec.md` 5.4의 전례 — 그 수정이 하루 넘게 안 먹었다).

**(d)를 뺀 이유는 조건이 성립하지 않아서다.** "로컬 전용이니 안 해도 된다"는
#42를 자른다는 전제 위에 선다. 그런데 4절이 그것을 자르는 조건으로 든 것은
**"일정이 밀리면"**이고, M4는 오히려 **두 달 앞당겨** 끝났다. **자를 조건이
아직 오지 않았으므로 자른다고 가정할 수 없다.**

### (a)가 두 결말 모두에 안전하다

**이 판단의 값은 #42의 거취를 기다리지 않아도 된다는 데 있다.**

| #42를 | (a)를 넣어 두면 |
|---|---|
| **한다** | `false`로 띄운다. 관리자 화면이 **아예 없다** |
| **자른다** | 아무것도 안 바뀐다. 프로퍼티가 하나 늘 뿐이다 |

**`holdfast.demo.enabled`와 같은 관용구다**(`scope-m4.md` 7절 — "로컬 시연 밖에서
켜 두지 않는다"). 새 개념이 아니라 이미 있는 판단을 한 곳 더 적용하는 것이다.

### 잠그는 것이 아니라 없애는 것이다 — 그래서 로컬은 그대로다

**(a)는 접근 제한이 아니다.** 켜면 누구나 열리고, 끄면 경로 자체가 없다.
**로컬에서 `/admin/**`을 누구나 여는 사실은 바뀌지 않는다** — 그 위에 선
서술들(`scope-m4.md` 8절의 "관리자라고 소유권 검사를 건너뛰게 만들지
않았다")도 그대로다.

**인증을 넣는 것도 아니다.** `rfp-scope.md` 4.3이 인증을 배제한 이유(k6가
`X-User-Id`로 사용자를 구분하므로 세션 인증이 붙으면 부하 시나리오를 전부
고쳐야 한다)는 그대로 유효하다.

### 측정에는 영향이 없다

**로컬은 켬이 기본값이므로 #105는 지금 그대로 잰다.** PER-002 화면 목록
(`rfp-scope.md` 2.3)에 관리자 화면이 다섯 이상 들어 있는데, (b)를 골랐다면 그
화면들에 자격증명이 필요해 **측정 절차가 늘었을 것**이다. (a)에는 그것이 없다.

k6가 실제로 치는 경로도 확인했다 — `/api/health`·`/api/status`·`/api/sessions`
·`/api/holds`·`/api/reservations` 다섯뿐이고 **`/admin/**`은 하네스를 지나지
않는다.**

**구현은 #124에 남는다.** 여기서 확정한 것은 수단과 근거이지 코드가 아니다.

#### `/actuator/**`도 같은 물음인데 답이 다르다 — 끄지 않고 좁힌다

**3.1이 `/admin/**`만 봤다.** `/actuator/**`는 그 검토에 들어가지 않았는데
같은 문장이 그대로 적용된다 — 인증이 없어 누구나 열고, 배포하면 인터넷에 나간다.
이슈 #156.

**지금 열려 있는 것을 실측했다.**

```
노출 엔드포인트  self, info, health, health-path, metrics
메트릭 항목      75개
예                jvm.memory.used, hikaricp.connections.pending, …
```

힙 사용량·커넥션 풀 상태·JVM 정보가 다 보인다.

**그런데 `/admin/**`처럼 끌 수가 없다.** `concurrency-spec` 7.1이 커넥션 풀
대기의 출처로 actuator를 못박았고, `metrics-snapshot.mjs`가 측정 중에 그것을
긁는다. **끄면 측정 지표가 하나 사라진다.**

##### 실행 모드로 가른다 — 시연과 측정은 같은 실행이 아니다

#156이 좁히는 안을 기각한 근거가 *"끄면 측정도 못 한다"*였는데, 그 전제가
성립하지 않는다. **측정과 시연은 서로 다른 명령으로 뜬다.**

| | 명령 | actuator | 근거 |
|---|---|---|---|
| 측정 | `./holdfast up` + `run.sh` | `health,info,metrics` | 7.1이 요구한다 |
| **시연** | **`./holdfast demo`** | **`health`만** | `localhost`라 노출은 없지만 **끄고 잃는 것도 없다** |
| 배포 | AWS | ALB 리스너 규칙으로 `/actuator/*` 거부 | 아래 |

**측정이 이 좁힘에 닿지 않는다는 것을 확인했다.**

- `metrics-snapshot.mjs`는 `app1`·`app2`(`:18081`·`:18082`)에 **직접 붙는다** —
  nginx도 `./holdfast demo`도 지나지 않는다
- `run.sh`는 `demo` 서브커맨드를 **쓰지 않는다**

그래서 `HOLDFAST_ACTUATOR_EXPOSURE`의 **기본값이 측정용**이고, 좁히는 것은
`./holdfast demo` 하나다. `holdfast.demo.enabled`·`holdfast.admin.enabled`와
같은 관용구이며(#124), **새 개념이 아니다.**

##### 근거가 터널에서 AWS 공개로 바뀌었다

**한때 이 절은 터널을 근거로 삼았다** — 시연을 개발 PC에 두고 터널로 여는 순간
개발 PC가 인터넷에 나가므로 **터널을 열기 전에 닫혀야 한다**고 적었다.
**2.1이 터널을 회수하면서 그 근거가 사라졌다.** `localhost`는 노출되지 않는다.

**그래도 이 절은 그대로 필요하다.** 2.1이 **AWS를 도메인 붙은 실제 서비스로**
열기로 했기 때문이다 — 노출 지점이 개발 PC에서 ALB로 옮겼을 뿐이고,
`metrics` 75개가 인증 없이 열린다는 사실은 같다.

**시연 쪽 좁힘(`./holdfast demo` → `health`만)도 유지한다.** 지금은 노출이
없지만 **끄고 잃는 것이 없다** — 발표자도 시연 중에 `metrics`를 보지 않는다.
조건이 다시 바뀌어도(터널을 되살리거나 화면을 밖에 열거나) 이쪽은 이미 닫혀 있다.

##### AWS 쪽은 리스너 규칙이다

#152가 **k6를 VPC 안 상자에서 돌리기로** 정했고(3.3), 그 상자는 앱 태스크에
프라이빗 IP로 직접 붙는다. **ALB에서 `/actuator/*`를 거부해도 측정에 닿지
않는다.** #156이 표에 적은 (a)이고, #152의 결론이 그 짝을 확정했다.

**Spring Security는 여전히 붙이지 않는다.** #138이 판정한 그대로 — 필터 체인은
경로를 가리지 않고 모든 요청에 붙어 측정 경로를 지난다.

### 3.2 로컬 nginx가 하는 일 중 ALB가 대신하지 않는 것

`nginx.conf` 첫 줄이 **"AWS로 옮기면 이 역할을 ALB가 대신한다"**고 적었다. 그런데
**무엇을 대신하고 무엇을 안 대신하는지**가 없었다. 이슈 #150.

`nginx.conf`는 짧다. 아래 표가 그 파일의 모든 줄을 덮는다 — 성격이 다 다르고,
**대응이 있는 줄과 없는 줄이 섞여 있다.**

| nginx | 왜 있나 | ALB에서 |
|---|---|---|
| `worker_connections 8192` | 기본 512로 VU 500을 때리면 nginx가 커넥션을 리셋하고 k6가 `status 0`으로 받아 **오류율 임계가 깨진다**. 실측에서 alert 394건 | **대응 개념이 없다** — ALB는 스스로 확장한다. 대신 다른 한계를 갖는다(아래) |
| `upstream` 앱 2대 | 로드밸런싱 | **타겟 그룹** |
| `proxy_set_header Host $http_host` | `$host`면 포트가 빠져 리다이렉트가 `localhost/`로 튄다. **하루 넘게 적용 안 된 전례**(`design-spec` 5.4) | **필요 없다** — ALB는 `Host`를 그대로 넘긴다. 대신 `use-relative-redirects`가 그때 값을 한다 |
| `X-Real-IP` · `X-Forwarded-For` | 관례로 넣었다. **앱은 읽지 않는다** | ALB가 `X-Forwarded-For`를 스스로 붙인다. 역시 앱은 안 읽는다 |
| `listen 80` (HTTP/1.1) | — | **HTTP/2 (기본 지원)** — 아래가 이 표에서 가장 크게 갈리는 줄이다 |

#### HTTP/1.1과 HTTP/2 — 브라우저 커넥션 제한이 여기서 사라진다

`scope-m4.md` 7절이 **"브라우저는 호스트당 커넥션을 6개로 제한한다"**를 적고, 그
제약 때문에 시연을 **좌석별 몰아치기**로 우회했다. **그 6개가 HTTP/1.1의
성질이라는 것과, ALB로 가면 사라진다는 것**이 어디에도 없었다.

HTTP/2는 커넥션 하나에 스트림을 다중화하므로 그 상한이 없다 — nginx 기본
`http2_max_concurrent_streams`가 128이고 ALB도 비슷한 규모다. **ALB는 HTTPS
리스너에서 HTTP/2를 별도 설정 없이 쓴다** — 그래서 로컬에 자체 서명 인증서를
만들어 흉내 낼 이유가 없다. 다만 그 리스너를 세우는 데 조건이 있다(아래).

**측정과 시연을 갈라서 본다.** 프로토콜을 한 손잡이로 다루면 안 된다 — 한쪽은
바뀌면 안 되고, 다른 쪽은 바뀌면 이득이다.

| | 프로토콜 | 왜 |
|---|---|---|
| **k6 측정** | **HTTP/1.1 고정** | M3의 27회가 HTTP/1.1로 측정됐다. 바꾸면 결과가 갈렸을 때 환경 탓인지 프로토콜 탓인지 구분되지 않는다 |
| **브라우저 데모** | **HTTP/2를 검토한다** | 6커넥션 제약이 사라진다. 아래 |

#### 브라우저 데모는 HTTP/2로 올리는 것을 검토한다

`scope-m4` 7절이 적은 제약이 시연 설계를 이미 한 번 바꿨다.

> **좌석 수가 6 이상이면 동시에 떠 있는 6개가 서로 다른 좌석으로 갈라져 애초에
> 겹치지 않는다.** `none`이어도 초과 홀드가 한 건도 안 생긴다.

**동시성을 보여 주는 화면이 동시성을 못 보여 줘서 좌석별 몰아치기로 우회했다.**
HTTP/2면 커넥션 하나에 스트림을 다중화하므로 그 우회가 통째로 없어지고, 한 좌석에
스무 건을 진짜로 동시에 던질 수 있다. **시연의 설득력이 여기서 갈린다.**

그래서 이것은 "안 정하고 넘어갈 것"이 아니라 **쫓아갈 방향**이다. 다만 공짜가
아니라서 조건을 함께 적는다 — 브라우저는 h2c를 지원하지 않으므로 **HTTP/2에는
TLS가 반드시 붙는다.**

| | 비용 | 걸리는 것 |
|---|---|---|
| **CloudFront를 앞에 세운다** | **~0** | 기본 도메인 `*.cloudfront.net`에 **유효한 인증서가 딸려 온다.** 도메인을 살 필요가 없고 경고도 없다 |
| 도메인 취득 + ACM | ~$12/년 | **destroy가 안 되는 유일한 항목.** 아래 |
| 자체 서명 인증서를 ACM에 가져오기 | 0 | **발표 중 브라우저 경고**가 뜬다 |
| 로컬 nginx에 HTTP/2 | 0 | 이미지에 모듈은 있다. 역시 자체 서명이라 경고가 뜬다 |
| 그냥 `:80` | 0 | 지금 그대로. 우회책을 계속 쓴다 |

**첫째를 우선 검토한다.** ALB에는 인증서를 붙이지 않고 CloudFront가 뷰어 쪽
TLS와 HTTP/2를 맡는다. 오리진 연결은 ALB `:80` HTTP로 두면 되므로 **ALB 구성이
지금과 같다.**

> **이 방향을 회수한다(#172). 지우지 않고 남기는 이유는 "검토했고 이 조건에서
> 뺀다"가 "검토한 적 없다"보다 강하기 때문이다** — `erd.md` 4.1이 쓰는 방식이다.
>
> **CloudFront를 검토한 목적이 사라졌다.** 목적은 **도메인 없이 유효한 인증서를
> 얻어 브라우저 6커넥션 제약을 우회하는 것**이었는데, 2.1이 **시연을 AWS 밖으로
> 옮겼다.** 라이브 시연은 집 PC에서 돌고 **청중은 붙지 않으므로**, AWS 쪽에
> 브라우저 다발이 오지 않는다. **6커넥션 제약이 걸릴 자리 자체가 없다.**
>
> **그리고 도메인을 확보했다 — `inhalab.cloud`, Cloudflare에서 Active다**(2.1).
> 도메인이 Cloudflare에 있으면 **무료 플랜이 엣지에서 TLS와 HTTP/2를 주므로**
> CloudFront도 ACM도 필요하지 않다. 위 표의 첫째가 가졌던 이점(*"도메인을 살
> 필요가 없다"*)이 양쪽에서 없어진 셈이다.
>
> **용도 서술이 두 번 바뀐 자리다.** 이 블록은 한때 도메인을 *"터널 주소용이고
> ALB용이 아니다"*(#175)라고 적었고 #176이 *"AWS 서비스 주소용"*으로 뒤집었다.
> **지금은 둘 다이며 서브도메인이 가른다** — `demo.` 터널, `app.` ALB(2.1).
>
> **그래서 CloudFront를 세우지 않는다.** 아래에 적은 값(구성 요소 하나 증가 ·
> 전파 시간 · **캐싱을 반드시 꺼야 한다**)을 치를 이유가 남지 않았다.

> **금액 논거를 회수한다(#172).** 이 절은 한때 *"도메인 $12는 데모 하루 비용의
> **6~12배**인 데다"*를 둘째를 뒤로 미는 근거로 썼다. **$12는 Route 53 기준이었고
> 저가 TLD를 다른 등록기관에서 사면 그 수준이 아니다** — 데모 하루($2)와 비슷하거나
> 낮다. **"6~12배"는 근거로 쓸 수 없다.**
>
> **`terraform destroy`가 안 듣는다는 성격은 남는다.** 시간당 과금이 아니라 1년치
> 선불이라 발표가 끝나도 남고, 5절의 안전장치 밖에 있다. 다만 **금액이 사소해져
> 판단을 가를 무게가 아니다.**
>
> **결론은 바뀌지 않지만 근거가 바뀌었다.** 한때 이 자리는 *"ALB에 HTTPS 리스너를
> 안 붙이는 근거는 시연이 AWS에 있지 않다는 것"*이라 적고 **도메인을 터널
> 주소용**으로 봤다. **2.1이 터널을 회수하면서 용도가 뒤집혔다** — 도메인은
> **AWS 서비스 주소용**이다.
>
> **그런데도 CloudFront를 세우지 않고 ACM도 붙이지 않는다.** 도메인을
> Cloudflare에 올리면 **무료 플랜이 엣지에서 TLS와 HTTP/2를 준다** — CloudFront가
> 주려던 것(도메인 없이 HTTPS)도, ACM이 주려던 것(ALB에 인증서)도 **둘 다 그
> 한 겹으로 대체된다.** 오리진 구간은 ALB 보안그룹을 Cloudflare IP 대역으로
> 좁혀 가린다(2.1).
>
> **k6는 여기에 닿지 않는다.** ALB `:80`으로 직결하므로 7.3의 `측정 프로토콜`이
> 그대로 유지된다.

CloudFront가 치르는 값도 적어 둔다.

- **구성 요소가 하나 는다.** HTTP/3 절에서 "CloudFront를 앞에 세우면 3절의 구성
  판단을 다시 해야 한다"고 적은 것과 같은 부담이다
- **배포 전파에 시간이 걸린다.** "데모 직전 apply"에 몇 분이 붙는다
- **캐싱을 반드시 꺼야 한다.** 좌석맵이 3초 폴링에 ETag·304를 쓰므로
  **CloudFront가 캐시하면 좌석 상태가 굳은 채로 보인다** — #157에서 고친 증상이
  인프라 계층에서 그대로 재현된다. `CachingDisabled` + **쿼리스트링·헤더 전량
  전달**이 필요하고, `?userId=`가 안 넘어가면 **시연이 통째로 안 돈다.** POST도
  허용 메서드에 넣어야 홀드 요청이 지나간다

**k6는 CloudFront를 지나지 않는다.** ALB `:80`으로 직접 쏘므로 측정 경로는
지금과 같다 — 위 표의 "k6 측정 HTTP/1.1 고정"이 그대로 성립한다.

**막히면 다섯째로 떨어진다.** 4절이 AWS를 "잘라도 되는 것"으로 보므로, 그때는
지금 우회책이 그대로 살아 있어 잃는 것이 없다.

위 대조표의 "HTTP/2 (기본 지원)"는 **뷰어 쪽에 TLS가 선 경우로 읽는다** —
ALB에 HTTPS 리스너를 세우거나, 첫째처럼 CloudFront가 그 자리를 맡거나다. ALB
`:80`만 두면 HTTP/1.1이고 6커넥션 제약이 그대로 남는다.

#### HTTP/3를 검토하고 뺐다

`nginx:1.27-alpine`에 `--with-http_v3_module`이 **이미 들어 있다.** 몇 줄이면
켜진다. 그래도 하지 않는다.

```
$ docker run --rm nginx:1.27-alpine nginx -V 2>&1 | grep -o -- '--with-http_v[0-9]_module'
--with-http_v2_module
--with-http_v3_module
```

- **동시성 관점에서 HTTP/2와 같다.** 둘 다 다중화하고 6개 제한이 사라지는 것도 같다
- HTTP/3의 이점은 **패킷 손실 시 head-of-line blocking이 없다**는 것인데, 로컬은
  손실이 사실상 0이라 **발현될 자리가 없다**
- **ALB가 HTTP/3를 지원하지 않는다.** 쓰려면 CloudFront가 필요하다 — 위에서 그
  CloudFront를 HTTP/2 때문에 이미 검토하므로 **추가 비용은 토글 하나로 줄었다.**
  그래도 앞의 두 근거가 그대로라 켤 이유가 없다

**UDP라서 뺀 것이 아니다.** QUIC은 재전송·순서 보장을 다시 구현해 신뢰성이 TCP와
같다. 뺀 이유는 **얻는 것이 없는데 구성 요소가 늘어서**다.

#### 배포 후 채울 자리 — 5.4의 실측 표

`design-spec` 5.4가 `Location` 조합 네 줄을 실측으로 남겼다. **ALB 줄이 비어
있다.** 배포하면 한 줄을 채운다.

| 앱 | 프록시 | 응답 `Location` |
|---|---|---|
| 상대 | nginx `$http_host` | `http://localhost:8080/admin/programs` ✅ |
| 상대 | nginx `$host` | `http://localhost/admin/programs` ❌ |
| 상대 | **ALB** | **미측정 — #42에서 채운다** |

**ALB는 `Location`을 그대로 흘린다.** 그래서 앱이 낸 상대 경로가 곧 정답이 되고,
절대 URL이었다면 ALB가 HTTPS를 끊고 앱에 HTTP로 넘기는 구성에서 `http://`로
리다이렉트해 브라우저가 막는다 — `use-relative-redirects`가 **값을 하는 곳이
여기다**(5.4).

#### `worker_connections`에 대응하는 ALB의 한계

**같은 개념은 없다.** ALB는 커넥션 수를 설정으로 받지 않고 스스로 확장한다.
다만 한계가 없는 것은 아니다.

- **워밍업이 필요하다.** 급격한 부하에 LCU가 따라오기 전 5xx가 날 수 있다.
  k6 시나리오가 이미 30초 웜업을 두므로(7.4) 그 창이 겹친다
- **유휴 타임아웃 기본 60초.** 이 프로젝트의 요청은 밀리초라 닿지 않는다

**로컬에서 `worker_connections`를 고정한 이유(측정 대상이 로드밸런서가 되지 않게)는
AWS에서도 같다.** 다만 손잡이가 설정이 아니라 웜업이다 — 첫 회차를 버리는 것이
그 대응이고, 7.4가 이미 그렇게 한다.

### 3.3 VPC 안에 상자 하나 — k6와 psql이 함께 쓴다

이슈 #152(부하 생성기 위치)·#153(RDS 시드 경로). **두 이슈를 함께 판정한다** —
둘 다 "VPC 안에 뭔가 필요한가"를 묻고 있어, 따로 정하면 리소스가 둘이 된다.

#### 먼저 취소할 것 — AWS는 재측정이 아니다

#152에 **"(a) VPC 안 EC2에서 돌리면 7.3의 `k6 실행 위치 — 앱과 분리된 호스트`가
처음으로 충족되고, 그러면 #42가 '배포했다'가 아니라 '측정 조건을 하나
개선했다'가 된다"**고 적었다. **그 방향을 취소한다.**

`concurrency-spec` 7.3이 이미 판정을 내려 뒀다.

> **이것은 확정된 한계이며 재측정으로 해소하지 않는다.** 이 표는 한때 "3개월차
> AWS 환경에서 k6를 별도 인스턴스로 분리해 다시 잰다"고 적었으나 그 약속은
> 회수했다 (…) **재측정 약속은 유효하지 않다**

근거가 셋 붙어 있다 — 27회 두 시간 반이 드는데 M3의 결론이 "p95로는 전략을
구분할 수 없다"(7.7.1)라 환경을 바꿔도 뒤집힐 여지가 적고, 이 문서 4절이 AWS를
"잘라도 되는 것"으로 본다. 본 문서 2절도 같은 말을 이미 하고 있다 — **"락 전략
비교표의 숫자는 로컬에서 뽑는다."**

**그래서 "k6를 어디서 돌리나"는 정본 측정의 문제가 아니다.** 질문이 훨씬 작아진다
— 배포한 것이 실제로 도는지 확인할 자리가 필요한가.

#### 판정 — 퍼블릭 서브넷에 작은 상자 한 대

| 용도 | 필수인가 |
|---|---|
| **RDS 시드** (`seed.sh` · `infra/demo-seed.sql`) | **필수.** 없으면 데모 자체가 안 된다 |
| k6 스모크 1회 | 선택. **정본이 아니다** — 결과를 전략 비교표에 넣지 않는다 |

**시드가 이 상자를 요구하므로 어차피 하나는 필요하다.** k6는 그 위에 얹는다.
이것이 두 이슈를 함께 정해서 얻는 전부다 — #152 때문에 인스턴스를 새로 만드는
것이 아니라, #153이 이미 요구하는 인스턴스를 #152가 나눠 쓴다.

#### NAT Gateway를 만들지 않는다

5절이 **"깜빡하면 가장 크게 샌다"**고 특히 경고한 항목이다. **상자를 퍼블릭
서브넷에 두면 NAT가 필요 없다** — 인터넷 게이트웨이로 직접 나가고, 앱·RDS·
ElastiCache에는 같은 VPC 안에서 프라이빗 IP로 닿는다.

#153이 늘어놓은 선택지 중 둘을 이 근거로 뺀다.

| | 왜 안 하나 |
|---|---|
| (a) 배스천 EC2 | 배스천을 프라이빗에 두면 **NAT가 붙는다.** 퍼블릭에 두면 그냥 이 상자다 |
| (b) RDS를 퍼블릭 서브넷에 | **DB를 인터넷에 내놓지 않고도 NAT를 피할 수 있다.** 감수할 이유가 없다 |
| (c) 시드를 ECS 태스크로 | 태스크 정의가 하나 더 늘고, 시드마다 태스크를 띄운다. **상자가 이미 있으면 이득이 없다** |

보안그룹은 세 줄이면 된다.

- 상자 ← **내 IP만** SSH(22)
- RDS ← 상자와 앱 태스크만 5432
- ElastiCache ← 앱 태스크만 6379 (`redis` 전략일 때만 띄운다, #155)

#### `seed.sh`는 그대로 돌지 않는다 — 고치지 않고 적어만 둔다

```bash
psql_run() {
  docker compose exec -T "$DB_SERVICE" psql -U "$DB_USER" -d "$DB_NAME" ...
}
```

**컨테이너를 전제한다.** 상자에는 compose도 `db` 컨테이너도 없다.

다행히 접속이 이 함수 하나에 모여 있어 **바꿀 곳은 한 군데다.** 그래도 지금
고치지 않는다 — #153이 "경로가 정해지기 전에 고치면 헛일이다"라고 적었고,
`load-test/`는 CODEOWNERS상 최건 소유다. **#42에서 실제로 붙일 때 함께 정한다.**

시드가 측정마다 도는 것도 그대로다 — 전략을 바꿀 때마다 U-2 인덱스를 지우거나
다시 만든다(`erd.md` 3.1). 한 번 넣고 끝나는 것이 아니라서 상자가 계속 필요하다.

#### k6는 AWS에서도 HTTP/1.1로 쏜다

3.2가 ALB의 HTTP/2를 적으면서 이 판단을 여기로 미뤘다. **스모크라도 프로토콜은
로컬과 같게 둔다.** 다르면 결과가 갈렸을 때 환경 때문인지 프로토콜 때문인지
구분되지 않아 스모크의 값이 사라진다.

브라우저 데모는 프로토콜이 달라도 상관없다 — 시연이지 측정이 아니다.

## 4. 우선순위 — 로컬·측정이 먼저다

**AWS 배포는 M2 이후 영역이며, 착수 순서상 로컬·측정보다 뒤에 둔다.**

설계서 5.3이 경고한 가장 흔한 실패("UI·인프라에 시간을 쏟다가 정작 동시성에
손을 못 댐")를 피하기 위해, AWS는 다음 조건이 충족된 뒤에만 착수한다.

1. 로컬 다중 인스턴스 환경 완료 ✅ (#11)
2. 베이스라인 실패 재현 데이터 확보 (M2)
3. 락 전략 4종 측정 진행 중 또는 완료

**설계서 8.1의 "잘라도 되는 것"에 AWS 배포를 포함한다.** 일정이 밀리면 AWS를
포기하고 로컬 측정만으로 마감한다. 로컬만으로도 프로젝트 논지는 100% 성립한다.
Fargate는 "여유가 있으면 얻는 보너스"이지 필수 산출물이 아니다.

## 5. 비용 관리 — "결제 상한"은 없다

**AWS에는 금액 초과 시 자동으로 차단하는 결제 상한 기능이 없다.** AWS Budgets는
알림만 제공하며 리소스를 끄지 않는다. 따라서 안전장치는 다음 두 가지다.

| 장치 | 역할 |
|---|---|
| **`terraform destroy`** | 데모 후 전체 리소스 즉시 삭제 (유일하게 확실한 방어) |
| **AWS Budgets 알림** | $5·$10 임계값 이메일 (조기 경보, 자동 차단 아님) |

운영 규칙:
- Terraform으로 apply/destroy. `apply`는 수동, CI는 `plan`까지만 (협업 규칙 준수).
- 데모 직전 `apply`, 발표 종료 즉시 `destroy`.
- **NAT Gateway를 특히 주의한다.** 시간당 과금이라 깜빡하면 가장 크게 샌다.
- destroy 후 콘솔에서 Fargate·RDS·ElastiCache·ALB·NAT·EIP가 모두 내려갔는지 확인.
- Fargate·RDS·ElastiCache는 프리티어 대상이 아니다. 크레딧에서 차감되므로
  받은 크레딧 잔량을 발표 전에 확인한다. 학생 크레딧(AWS Educate / GitHub
  Student Pack)이 있으면 우선 활용한다.

## 6. 미결정 항목 처리 (설계서 0.3)

| 항목 | 결정 |
|---|---|
| ECS Fargate vs EC2 | **Fargate** (본 문서 3절) |
| RDS·ElastiCache 마이너 버전 | PostgreSQL 18 / Redis 7 — 로컬 이미지와 일치시켜 이식성 확보 |
| 부하 생성기 위치 (#152) | **VPC 안 상자에서 스모크만.** 정본 측정은 로컬 (3.3) |
| RDS 시드 경로 (#153) | **같은 상자에서 psql.** NAT 없이 퍼블릭 서브넷 (3.3) |
| ALB 프로토콜 | **브라우저 데모는 HTTP/2를 검토한다** — CloudFront 기본 도메인 우선(도메인 구매 불필요). **k6는 항상 HTTP/1.1** (3.2·3.3) |

RDS·ElastiCache의 구체 마이너 버전은 실제 프로비저닝 시점에 AWS가 제공하는
최신 안정 마이너로 고정하고 Terraform 변수에 명시한다.
