# 배포 환경 결정 (#8)

`docs/concurrency-spec.md` 0.3절이 박태준에게 M1 기한으로 지정한 결정 항목이다.
AWS를 쓸지, 쓴다면 어떤 형태로 할지를 여기서 고정한다.

## 결론 요약

| 항목 | 결정 |
|---|---|
| 측정 주력 | **로컬 Docker Compose** (통제된 환경, 재현성 우선) |
| AWS 사용 | **목표로 둔다. 단 측정·로컬 완료 이후 착수** |
| AWS 형태 | **ECS Fargate** (앱 2대 + ALB + RDS + ElastiCache) |
| 우선순위 | 로컬·측정이 먼저. AWS 배포는 여유가 생기면 진행 |
| DB·캐시 버전 | RDS PostgreSQL 18 / ElastiCache Redis 7 (로컬과 일치) |

## 1. 판단 기준 (#8 이슈)

세 가지 기준으로 판단했다.

- **다중 인스턴스 2대 + 공유 Redis 구성이 가능한가** — 로컬에서 이미 구현·검증 완료(앱 2대 + nginx + Redis, k6 부하 테스트 통과).
- **4개월간 비용이 감당 가능한가** — 아래 2절.
- **부하 테스트 결과의 재현성이 확보되는가** — 로컬이 통제된 환경이라 재현성이 더 높다.

## 2. 측정은 로컬에서 한다

부하 테스트만 놓고 보면 로컬/온프레미스가 통제된 환경이라 측정이 더 깔끔하다.
네트워크 변수가 끼지 않고, 반복 실행이 자유롭고, 비용이 들지 않는다. 설계서
7.3의 고정 변수 표(커넥션 풀·스레드 풀·격리 수준 등)를 로컬에서 완전히 통제할
수 있다.

**AWS는 "측정을 더 잘하려고"가 아니라 "클라우드에 실제 배포도 했다"를 보이는
별개 목적으로 선택한다.** 락 전략 비교표의 숫자는 로컬에서 뽑는다.

## 3. AWS 형태 — ECS Fargate

EC2와 Fargate를 비교했다.

| | EC2 | ECS Fargate |
|---|---|---|
| 데모 1회 비용 | ~$1 | ~$1–2 |
| 월 방치 시 | $70–80 | $120–130 (+ NAT $45) |
| 설정 공수 | 낮음 (compose 그대로) | 높음 (태스크 정의·서비스·네트워킹) |
| 클라우드 경험·발표 임팩트 | 보통 | 높음 |

**Fargate를 택한 이유는 서버리스 컨테이너 오케스트레이션 경험이다.** 측정
품질에는 EC2와 차이가 없으므로, 이 선택의 근거는 전적으로 학습·발표 가치에
있다. 데모는 잠깐 띄우고 즉시 내리는 방식이라 1회 비용 차이는 무시할 수준이다.

Fargate 단가(2026, Linux/x86): vCPU 시간당 $0.04048, 메모리 GB당 시간당
$0.004445. 앱 2대(각 1 vCPU / 2 GB) + ALB + RDS(db.t3.micro) + ElastiCache
(t3.micro) 기준 시간당 약 $0.17. 반나절 데모 약 $1, 하루 약 $2.

### 3.1 배포하면 `/admin/**`을 끈다 — 잠그는 것이 아니라 없앤다

**결론: `holdfast.admin.enabled` 프로퍼티로 끈다. 로컬은 켬(기본값), 배포는
끔.** 이슈 #124의 판단 항목이며 여기서 확정한다.

### 무엇이 문제인가

`/admin/**`은 **누구나 연다.** 인증이 없기 때문이고, 그 사실은
`scope-m4.md` 8절·`rfp-scope.md` 3장·`demo-script.md` 4절에 이미 적혀 있다.
**지금은 로컬 Docker Compose에서만 도므로 노출이 없다**(2절). 그런데 #42로
ALB 뒤에 뜨면 **관리자 화면이 열린 채 인터넷에 나간다.**

### 네 선택지와 판정

| 수단 | 측정 경로 | 판정 |
|---|---|---|
| **(a) `holdfast.admin.enabled` 프로퍼티** | 안 닿는다 — 빈을 아예 안 만든다 | **채택** |
| (b) nginx `auth_basic` | 안 닿는다 — k6는 `/api/*`만 친다 | **기각 — 아래** |
| (c) Spring Security를 `/admin/**`에만 | **닿는다** — 필터 체인이 `/api/holds`도 지난다 | **기각** |
| (d) 하지 않는다 | — | **기각** |

**(c)를 먼저 뺀다.** 필터 체인은 경로를 가리지 않고 모든 요청에 붙는다.
`concurrency-spec.md` 7.8이 **확정 트랜잭션에 INSERT 한 문장 늘어난 것을 세 번
재고도 판정하지 못했다** — 측정 경로에 무엇을 더할 때 드는 값이 그만큼이다.
그리고 #105가 곧 PER-002를 다시 잰다.

**(b)가 정반대인 이유가 이 판정의 핵심이다.** `nginx.conf` 첫 줄이 적어 두었다 —
**"AWS로 옮기면 이 역할을 ALB가 대신한다."** 즉 nginx는 **로컬에만 있다.**
`auth_basic`을 걸면 **노출이 없는 로컬에는 자물쇠가 걸리고, 노출이 있는 AWS에는
안 걸린다.** 거기에 비밀번호 파일이 하나 늘고, `nginx.conf`를 고치면 reload가
필요하다(`design-spec.md` 5.4의 전례 — 그 수정이 하루 넘게 안 먹었다).

**(d)를 뺀 이유는 조건이 성립하지 않아서다.** "로컬 전용이니 안 해도 된다"는
#42를 자른다는 전제 위에 선다. 그런데 4절이 그것을 자르는 조건으로 든 것은
**"일정이 밀리면"**이고, M4는 오히려 **두 달 앞당겨** 끝났다. **자를 조건이
아직 오지 않았으므로 자른다고 가정할 수 없다.**

### (a)가 두 결말 모두에 안전하다

**이 판단의 값은 #42의 거취를 기다리지 않아도 된다는 데 있다.**

| #42를 | (a)를 넣어 두면 |
|---|---|
| **한다** | `false`로 띄운다. 관리자 화면이 **아예 없다** |
| **자른다** | 아무것도 안 바뀐다. 프로퍼티가 하나 늘 뿐이다 |

**`holdfast.demo.enabled`와 같은 관용구다**(`scope-m4.md` 7절 — "로컬 시연 밖에서
켜 두지 않는다"). 새 개념이 아니라 이미 있는 판단을 한 곳 더 적용하는 것이다.

### 잠그는 것이 아니라 없애는 것이다 — 그래서 로컬은 그대로다

**(a)는 접근 제한이 아니다.** 켜면 누구나 열리고, 끄면 경로 자체가 없다.
**로컬에서 `/admin/**`을 누구나 여는 사실은 바뀌지 않는다** — 그 위에 선
서술들(`scope-m4.md` 8절의 "관리자라고 소유권 검사를 건너뛰게 만들지
않았다")도 그대로다.

**인증을 넣는 것도 아니다.** `rfp-scope.md` 4.3이 인증을 배제한 이유(k6가
`X-User-Id`로 사용자를 구분하므로 세션 인증이 붙으면 부하 시나리오를 전부
고쳐야 한다)는 그대로 유효하다.

### 측정에는 영향이 없다

**로컬은 켬이 기본값이므로 #105는 지금 그대로 잰다.** PER-002 화면 목록
(`rfp-scope.md` 2.3)에 관리자 화면이 다섯 이상 들어 있는데, (b)를 골랐다면 그
화면들에 자격증명이 필요해 **측정 절차가 늘었을 것**이다. (a)에는 그것이 없다.

k6가 실제로 치는 경로도 확인했다 — `/api/health`·`/api/status`·`/api/sessions`
·`/api/holds`·`/api/reservations` 다섯뿐이고 **`/admin/**`은 하네스를 지나지
않는다.**

**구현은 #124에 남는다.** 여기서 확정한 것은 수단과 근거이지 코드가 아니다.

## 4. 우선순위 — 로컬·측정이 먼저다

**AWS 배포는 M2 이후 영역이며, 착수 순서상 로컬·측정보다 뒤에 둔다.**

설계서 5.3이 경고한 가장 흔한 실패("UI·인프라에 시간을 쏟다가 정작 동시성에
손을 못 댐")를 피하기 위해, AWS는 다음 조건이 충족된 뒤에만 착수한다.

1. 로컬 다중 인스턴스 환경 완료 ✅ (#11)
2. 베이스라인 실패 재현 데이터 확보 (M2)
3. 락 전략 4종 측정 진행 중 또는 완료

**설계서 8.1의 "잘라도 되는 것"에 AWS 배포를 포함한다.** 일정이 밀리면 AWS를
포기하고 로컬 측정만으로 마감한다. 로컬만으로도 프로젝트 논지는 100% 성립한다.
Fargate는 "여유가 있으면 얻는 보너스"이지 필수 산출물이 아니다.

## 5. 비용 관리 — "결제 상한"은 없다

**AWS에는 금액 초과 시 자동으로 차단하는 결제 상한 기능이 없다.** AWS Budgets는
알림만 제공하며 리소스를 끄지 않는다. 따라서 안전장치는 다음 두 가지다.

| 장치 | 역할 |
|---|---|
| **`terraform destroy`** | 데모 후 전체 리소스 즉시 삭제 (유일하게 확실한 방어) |
| **AWS Budgets 알림** | $5·$10 임계값 이메일 (조기 경보, 자동 차단 아님) |

운영 규칙:
- Terraform으로 apply/destroy. `apply`는 수동, CI는 `plan`까지만 (협업 규칙 준수).
- 데모 직전 `apply`, 발표 종료 즉시 `destroy`.
- **NAT Gateway를 특히 주의한다.** 시간당 과금이라 깜빡하면 가장 크게 샌다.
- destroy 후 콘솔에서 Fargate·RDS·ElastiCache·ALB·NAT·EIP가 모두 내려갔는지 확인.
- Fargate·RDS·ElastiCache는 프리티어 대상이 아니다. 크레딧에서 차감되므로
  받은 크레딧 잔량을 발표 전에 확인한다. 학생 크레딧(AWS Educate / GitHub
  Student Pack)이 있으면 우선 활용한다.

## 6. 미결정 항목 처리 (설계서 0.3)

| 항목 | 결정 |
|---|---|
| ECS Fargate vs EC2 | **Fargate** (본 문서 3절) |
| RDS·ElastiCache 마이너 버전 | PostgreSQL 18 / Redis 7 — 로컬 이미지와 일치시켜 이식성 확보 |

RDS·ElastiCache의 구체 마이너 버전은 실제 프로비저닝 시점에 AWS가 제공하는
최신 안정 마이너로 고정하고 Terraform 변수에 명시한다.
