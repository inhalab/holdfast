# 발표 자료 생성기

**자료의 정본은 이 스크립트다**(`#217`). `.pptx` 는 **산출물**이고 저장소에
없다 — 손으로 고치지 않는다.

## 구성

```
engine.py    좌표 하나로 pptx 와 HTML 미리보기를 같이 뽑는다. 색·글꼴·세로 자리
wk4.py       4주차 (2026-09-20 발표분). **다시 뽑지 않는다** — 아래 「4주차」
build/       도식 PNG. 산출물이라 커밋 안 한다
preview/     HTML 미리보기. 산출물이라 커밋 안 한다
```

## 왜 스크립트가 정본인가

한때 **좌표에서 생성하는 스크립트**와 **직접 고친 `.pptx`** 가 둘 다 원본 행세를
했고, **이미 갈려 있었다**(`#216`). 스크립트로 다시 뽑으면 저쪽이 고친 것이
되돌아가고, 저쪽을 고치면 스크립트와 조용히 갈린다.

**저장소 안이라는 것 하나로 갈렸다** — 리뷰가 붙고, PR 로 남고, 틀린 문장을
지우지 않고 회수할 수 있다. `.pptx` 는 그 셋 중 아무것도 못 한다.

## 발표자 노트 — 저장소 밖이다

| | 어디 | 왜 |
|---|---|---|
| 생성기 | **여기** | 리뷰·회수·공개 추적이 따라온다 |
| **노트 본문** | `docs/submissions/<회차>-노트.md` | **저장소가 공개다.** 「안 할 말」과 예상 질문이 들어간다(`#227`) |
| `.pptx` | `docs/submissions/` | 생성기가 노트를 읽어 넣은 **산출물** |

**`docs/submissions/*` 가 이미 무시한다.** 그래서 노트는 쓴 사람 로컬에만 있고,
생성기는 **있으면 읽고 없으면 경고만 하고 넘어간다.**

이렇게 해서 **다시 뽑아도 노트가 사라지지 않는다.** 한때 `.pptx` 안에만 있어서
11장 중 10장을 한 번 잃었다.

### 형식 — 칸이 셋이다

```markdown
### 슬라이드 1
말할 것 — 짧게.
예상 질문과 답 — …
어디 있나 — concurrency-spec.md 7.2.4
```

**긴 설명을 여기 쓰지 않는다.** 노트가 저장소 문서의 내용을 **다시 적으면**,
그 문서가 고쳐져도 노트는 안 따라온다 — 실제로 그렇게 낡은 문장 둘이 4주차
9번 노트에 남았다(`#220` 이 회수한 것을 노트만 들고 있었다). **「어디 있나」로
가리키면 원본이 고쳐지는 순간 노트도 맞다.**

### 누가 쓰나

**그 회차의 발표자가 쓰고, 생성기도 발표자가 돌린다.** 노트 파일이 무시되는
파일이라 쓴 사람 로컬에만 있기 때문이다 — 쓰는 사람과 돌리는 사람이 다르면
파일을 손으로 넘기게 되고 사본이 다시 둘이 된다.

**노트는 PR 리뷰를 안 탄다.** 그래서 발표 전에 상대가 공유 자리의 `.pptx` 를
한 번 읽는다(`#217` 결정 1).

## 돌리는 법

```bash
pip install python-pptx

# 도식이 들어가는 회차라면 PNG 를 먼저 뽑는다 (정본은 SVG 다)
mkdir -p tools/deck/build
chrome --headless=new --disable-gpu --window-size=1600,900 \
  --screenshot=tools/deck/build/deploy-architecture.png \
  docs/figures/deploy-architecture.svg

cd tools/deck && python wk4.py
```

**미리보기를 먼저 쓴다.** `.pptx` 가 PowerPoint 에 열려 있으면 저장이 거부되는데,
그때 미리보기까지 못 만들면 「무엇이 바뀌었나」를 볼 방법이 같이 사라진다.

> **이 기계에 LibreOffice 가 없어 `.pptx` 를 그림으로 못 뽑는다.** 그래서
> `engine.py` 가 같은 좌표 목록에서 HTML 도 만든다 — 글꼴도 좌표도 같으므로
> 미리보기가 거짓말할 여지가 좁다. 배치를 새로 짤 때는 이쪽을 본다.

## 세로 자리는 `engine.py` 한 곳에 있다

```
BAND_Y  500.0   6.94"   어두운 띠
BAND_H  133.9           바닥이 8.80" 가 된다
NOTE_DY 155.2           꼬리 = BAND_Y + NOTE_DY = 9.10"
SUB_Y   120.96  1.68"   머리글 부제
```

**한때 장마다 손으로 박혀 있었다.** 띠가 `464` · `470` · `500` 셋이었고 꼬리가
그때마다 「띠 + 158」 로 따라 적혀 **여덟 곳에 같은 관계가** 있었다. 띠 높이를
한 번 바꾸면 여덟 곳을 다 고쳐야 하고, 하나 빠뜨리면 그 장만 어긋난다.

**띠 본문은 2줄이 상한이다.** 띠 바닥이 `8.80"` 에 고정이라 셋째 줄이 잘린다 —
초안이 3줄이 되어 실제로 잘렸다(`#216`). 문서에만 적으면 또 밟으므로
**`band()` 가 세고 넘치면 경고한다.**

## 4주차 — 다시 뽑지 않는다

발표가 끝났고, 보관본은 발표에 쓴 `4주차_발표.pptx` 다(`#217` 결정 3).
`wk4.py` 가 여기 있는 이유는 산출물을 만들기 위해서가 아니라 **「그 자료를
무엇이 만들었나」가 저장소에 있어야 하기 때문**이다.

`#216` 이 자료 쪽에서 고친 문안과 좌표는 **이 스크립트로 옮겨 왔다.**
**대조는 `.pptx` 를 가진 쪽만 할 수 있다.** 노트는 옮기지 않았다.

## 5주차부터

`wk4.py` 를 베끼지 말고 `engine.py` 를 그대로 쓰되 **내용만 새로 짠다.**
배치는 내용에 맞춰 정하고, 색·글꼴·세로 자리는 `engine.py` 에서 온다.
